# Dispatcher recovery from Go

The conversation's actions menu opens **Dispatcher recovery** for the selected paired desktop's visible Dispatcher chat. It shows the chat's chosen name and desktop, and keeps these operations separate:

| Control | Effect | Evidence and gate |
| --- | --- | --- |
| Interrupt chat turn | Interrupt the visible chat's current turn, retaining the conversation. Provider runtimes may stop when they cannot interrupt. | Existing `chat.interrupt`, current advertised chat capability and app session; separate confirmation. |
| Stop chat session | Request a stop of the visible chat process, retaining saved conversation. Starting again is separate. | Existing `agent.stop`; a request is not a stopped acknowledgment. Go keeps the pending state until the desktop reports the chat sleeping. |
| Start new chat | Clear only the visible conversation. Memory, agents, connections, Actions, settings and the work controller stay. | Fresh `dispatcher/settings` confirmation, explicit human confirmation and `dispatcher.clearChat`; stale state requires a new confirmation. |

Stop and Interrupt confirmations bind the exact host, visible-chat target, epoch and app session. A replaced session or changed availability refuses the confirmation without a new command. New chat consumes its local prompt before awaiting dispatch. An uncertain new-chat reply locks further mutations for that target in the retained Store; reopening or equal reads cannot establish whether the clear ran. This is client-lifetime protection, not a durable cross-process/backend idempotency guarantee. The existing host confirmation-consumption race documented by the desktop audit remains a host-owned gap.

The hidden work controller has a different identity and is never substituted for the visible chat. At desktop `ae56577af786b0db79f21d137d0b334a5f7847dc`, its dedicated history route is desktop-network-only, with membership and agent-read grants. Go does not route around it. Desktop's **Restart Dispatcher** replaces the controller conversation (`work` keeps the visible chat; `both` clears it too), quarantines its old session and cancels queued/in-progress controller requests. Neither generic stop/wake nor clearing the visible chat is equivalent. Controller history and restart remain explicitly unavailable pending a host-owned, advertised phone contract. No new grants or low-level WebSocket fallback are introduced.

Other applicable desktop menu functions already have Go surfaces: agent settings, conversation archive, context/plan limits, and independently authorized terminal attachment. Desktop pop-out and local setup windows are desktop-specific. Delete is not offered for the Dispatcher. This slice adds no generic destructive/debug operation under a read grant.

Proof is pending. Six new package methods cover target isolation, cancellation/once consumption, lost-clear locks, stale reconfirmation, replaced-session refusal and stop-request-versus-sleep evidence through the existing scripted transport. Two native methods use an opt-in socket-free preview fixture; their synthetic records must prove exactly one visible-chat interrupt plus one clear in the first invocation, and one visible-chat stop in the second, with no controller/start/restart command. Both cancellation paths must send nothing. Native screenshots, current action routing, full-row geometry, actual method outcomes and cleanup require independent review before acceptance. No real Dispatcher stop, restart or reset is part of this proof.
