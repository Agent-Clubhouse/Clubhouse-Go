# Annex distributed trace context, version 1

HTTP: W3C traceparent: 00-<32 lowercase hex nonzero traceID>-<16 lowercase hex nonzero spanID>-<2 lowercase hex flags>. Sent only while local collection enabled, on exact pinned/authenticated Annex API and WS upgrade requests. Host validates before adopting as server parent; invalid/duplicate headers ignored, never auth/trust input. No baggage. Optional tracestate syntax validated (512B/32 members) but mobile drops vendor values until approved collector vendor-key policy exists.

Async turn: optional TOP-LEVEL `traceContext: {traceparent: string, tracestate?: string}` on inner chat event (alongside sessionId, seq, type, data), specifically turn_started. Context must represent a per-turn host span parented to originating accepted command, NOT WebSocket connection. Receipt may carry same optional field for diagnostics, but mobile does not use receipt to guess which turn starts. Native desktop-originated turns get independent server context. Preserve context unchanged when replaying historical events. Mobile live stream child only on new turn_started; history doesn't emit live spans. No links between unrelated turns.

Reconnect: new independent trace for each attempt; HTTP/TLS/read/snapshot within that attempt; no connection parent attached to all agent commands. Request retries preserve existing idempotency semantics; trace headers do not enter command body/digest/cache key. Capture Off strips outgoing trace/baggage headers. Session capture resets at next launch; Always persists preference only. No remote exporter active.
