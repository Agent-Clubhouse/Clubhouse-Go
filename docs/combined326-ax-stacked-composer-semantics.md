# Unapplied AX stacked-composer test semantics proposal

The accepted accessibility layout is a VStack: readable editor above the action rail. The two legacy midY-centering predicates in this AX-only method contradict that contract; ordinary-size centering and multiline growth tests remain byte-identical. Historical three cloud failures stop at the initial placeholder, before typing.

This candidate changes only the AX method/comment, retaining its historical method name for traceability, launch arguments, existing navigation bound, one focus tap/type and original final image. It replaces the two obsolete centering checks with full editor/action containment against navigation and full keyboard/input/assistant occlusion, positive finite actual frames, editor width at least70% of app (existing compact AX contract), editor above Send, Send44 minimum, editor hittability and typed Send enabled/hittable plus exact draft. It does not require a44pt text line, change fonts, widen tolerances or reinterpret floating values. New original images precede geometry. No extra wait/gesture/refocus/retry.

Strict native export prerequisites and lack of initial keyboard are explicit candidate assumptions requiring independent source review; unsupported shape fails. Queried input rectangles are not a native hit-test ownership proof. Source-only/unapplied; no parse, SDK/typecheck, build, test or simulator. Current screenshot/case success is not claimed. This does not fix unknown context reports, contextButton36, Retry42.248, the floating-boundary observations, or keyboard dismissal. No shared/product changes.

The independently reviewed Bool successor makes the five explicit shape/finite/intersection guards return false and guards both outer calls. An initial shape rejection therefore stops before the original focus/type actions; a typed-state shape rejection stops before the original final capture. Other XCTest assertions retain the existing continueAfterFailure policy and do not all return false. Inherited composer.firstMatch and Send selectors are unchanged, not new uniqueness proof. Initial keyboardCount0 and editing software Keyboard/inputView1 with at most one visible assistant are explicit fixture preconditions. Hardware keyboards, offscreen assistant exports or changed native names fail as unsupported test geometry, not automatically as product defects. No app-wide Window count1 assumption is introduced.
