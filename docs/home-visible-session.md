Home rendering and Recent sessions (Refs #528, Refs #549)

Home's State owner stays in its Tab and NavigationStack. Its expensive content exists only when Home is the selected tab and that tab's path is empty. Sheets live on an always-mounted VStack outside the condition. Arrange captures its entries when opened so a pending sheet never evaluates Home's hidden scope/layout. Root badges, connection reconciliation, Dispatch and execution-time action checks remain live.

A visible content construction computes one HomeLayout and passes it to the project list, animation and New agent action. The header uses the group's already-computed live status rather than recomputing project recency. This is not a memoized display-projection cache; narrowly keyed projection caching remains a follow-up.

Recent uses the existing CompanionListHold for the entire visible session. Activity/status/text changes update rows without re-sorting held peers. New projects/agents append after existing peers in catalog order, helpers stay under their real parent, and removals disappear. Newly displayed peers join the hold. Leaving Home (including pushing a page) ends the session; returning sorts fresh. Changing desktop scope or sort starts the appropriate new order. Name/custom retain their existing sort and temporary scroll hold. Pin/Inactive and live versus quiet/idle section membership retain their existing semantics; the snapshot governs recency order, not command authority or those structural states. No pull-to-refresh is added.

Recent held builds skip activity-based sorting for both projects and agent trees. They continue evaluating live status, shared Pin/Inactive state and idle/fold membership. No state/capability/identity guard is cached: all existing tap-time resolutions stay intact.

List removal has an explicit public ScrollViewReader restore. Home-only row markers record full identities and global rectangles into non-observable, value-only bookkeeping. Geometry never writes observable Home state. A saved row and its relative alignment survive tab/route changes; scope changes reset the anchor. If the row disappeared or moved into a closed fold, restoration explicitly falls back to the top. The modifier is a no-op in other screens. No UIKit introspection, private selectors or live configuration are involved.

DEBUG counters are opt-in and contain only closed counter kinds, synthetic test navigation bindings and value projection snapshots. The hosted class mounts the actual Root with 4 generated desktops, 96 projects and 1,152 agents including linked copies. It delivers 100 accepted text chunks in ten independently rendered batches. Separate cases cover pushed routes, fresh state/scope/folds on return, stable Recent status/newcomers/removals and a real UIKit List scroll followed by SwiftUI row-anchor restoration. The mounted test alone walks UIKit to find its own List; production code does not. Polling waits are condition-based and bounded, and actions are not retried.

The package session tests count activity-provider calls and cover status changes, new/removed peers, fresh order, Name/custom and helper ancestry. Existing AgentTree/AgentRow and LargeCatalog coverage is retained. No result is claimed until the orchestrator admits the separate build/test manifest. Physical battery/CPU improvement still needs measurement in the installed configuration; counter tests establish avoided Home work rather than a percentage CPU reduction.
