Home rendering and Recent sessions (Refs #528, Refs #549)

Home's State owner stays in its Tab and NavigationStack. The expensive List unmounts ONLY when the Home TAB is deselected. The Clubhouse navigation title, toolbar, project-error alert and pending sheets live on the always-mounted owner. Arrange captures its entries when opened. Root badges, connection reconciliation and Dispatch remain live.

Pushing an agent or Project page keeps the existing Home List mounted as the native transition/backdrop. On entering the pushed route, a Home-only value snapshot captures display inputs once: catalog/hosts, attention, layout, finished runs, row context, status/activity and permission/menu presentation. The concrete rendering child receives these values, then its Equatable boundary suppresses parent-driven rebuilding while pushed. This is NOT sufficient on its own: the Dispatcher row, connection banner and shared menu bodies also receive optional captured display inputs, and Home's agent-menu environment receives value-only display closures. None of those frozen descendants reads the Store in its body. Nil is the ordinary live path for every non-Home caller. App-update links receive a host value; only their destination reads the Store, when actually opened. Agent labels/tree rows use value agents and Preferences, not Store data.

AgentMenu and its nested menu items ordinarily invoke settings.canOpen, wake.choices and terminal.availability during rendering. Frozen Home supplies captured values for those queries. Their activation closures recheck the original live predicates before opening or issuing any action. Home captures those existing execution handles, plus the Open agent/Review State-writing callbacks, separately at push and passes them explicitly: the frozen row modifier never subscribes to Root’s freshly recreated permission Environment closures. The handles are cleared on pop/tab exit; no new task or reference owner is introduced. Display closures are constructed once at push. A constant modifier chain transforms incoming environment keys into those same values; no conditional modifier branch removes/recreates the List during freeze/thaw. The project Pin/Inactive/Wake/Terminal execution guards are unchanged and resolve identity/capability from the real Store. Display snapshots never authorize an action.

On pop, the very first content construction ignores the snapshot and reads fresh status/connection/permission inputs. The Recent hold survives the push/pop, so Back refreshes text/badges without shuffling peers. A visible content construction computes ONE HomeLayout and passes it to both the project list and animation hold; entering a push constructs one additional display snapshot. The header reuses the group's computed live status. A memoized display projection for visible Home remains a separate follow-up.

Recent uses CompanionListHold for the whole Home TAB session, including pushed routes. Activity/status/text changes update rows without sorting held peers. New projects/agents append after existing peers in catalog order, helpers stay under their real parent, and removals disappear. Newly displayed peers join the hold. A tab switch away, desktop scope/sort change, or app backgrounding ends the session; returning to Home starts fresh. Name/custom keep their existing sort and temporary scroll hold. Pin/Inactive and active/quiet/idle membership retain their structural semantics; only recency order is held. No newcomer cue or pull-to-refresh is added.

List removal has an explicit public ScrollViewReader restore. Home-only row markers record full identities and global rectangles in a lazily allocated optional, non-observable, value-only anchor holder. Geometry never writes observable Home state. A saved fully visible row (or the first intersecting row when none is contained) and its relative alignment survive tab/route changes; scope changes reset it. A missing/closed-fold target explicitly falls back to the top. Restoration clears on interaction, suspension, successful target geometry or at most 64 geometry callbacks. The marker is a no-op elsewhere. There is no UIKit introspection in production.

Home's project-error alert remains mounted but does not present over a pushed page. Once the Project page's inline error appears, it retains its displayed text locally and clears the shared error, so Back cannot replay it as a second alert.

DEBUG counters distinguish the cheap owner from content/scope/attention/layout/header/quiet construction and the actual row, agent-menu, shared-project-menu, quiet-child and connection-banner bodies. The real-Root hosted fixture uses 4 generated desktops, 96 projects and 1,152 agents with linked copies. Both Dispatch-hidden and pushed-agent tests accept 100 chunks in ten independently rendered batches. The pushed case requires zero expensive-counter changes, including row/menu children, and checks current connection presentation on the first pop construction. Other cases cover stale frozen activation, same-session Recent order, sort/scope resets, Pin/idle section moves, and saved anchor alignment within 8pt after both a tab round trip and a push/pop. Only tests traverse their own UIKit List. A real UI edge swipe asserts title/back label/nonblank content before and after; mid-gesture continuity is recording evidence ONLY, never a claimed assertion.

Package session tests count activity-provider calls and cover status/new/removed peers, fresh order, Name/custom and helper ancestry. Existing AgentTree/AgentRow and shared row/menu tests remain unchanged. All checks are UNRUN pending explicit per-ticket admission. No CPU-percentage or battery claim follows from hosted counters alone; installed-configuration performance measurement remains separate.
