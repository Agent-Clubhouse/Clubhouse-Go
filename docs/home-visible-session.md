Home rendering and Recent sessions (Refs #528, Refs #549)

Home's State owner stays in its Tab and NavigationStack. The expensive List unmounts ONLY when the Home TAB is deselected. The Clubhouse navigation title, toolbar, project-error alert and pending sheets live on the always-mounted owner. Arrange captures its entries when opened. Root badges, connection reconciliation and Dispatch remain live.

Pushing an agent or Project page keeps the existing Home List mounted as the native transition/backdrop. Before constructing the first pushed content, a non-published render-session storage synchronously captures Home-only display inputs once: catalog/hosts, attention, layout, finished runs, row context, status/activity and permission/menu presentation. Every Home value copy, including lazy List closures created before the push, reads the authoritative non-observable render-session snapshot; clearing it on pop restores the live path everywhere. Its Equatable rendering boundary suppresses parent-driven rebuilding while pushed. This is NOT sufficient on its own: the Dispatcher row, connection banner and shared menu bodies also receive optional captured display inputs, and Home's agent-menu environment receives value-only display closures. None of those frozen descendants reads the Store in its body. Nil is the ordinary live path for every non-Home caller. App-update links receive a host value; only their destination reads the Store, when actually opened. Agent labels/tree rows use value agents and Preferences, not Store data. The frozen Dispatcher row receives its execution callback explicitly; only the nil/default live wrapper reads the open-agent Environment closure. Its value-content child is counted separately.

AgentMenu and its nested menu items ordinarily invoke settings.canOpen, wake.choices and terminal.availability during rendering. Frozen Home supplies captured values for those queries. Their activation closures recheck the original live predicates before opening or issuing any action. Home captures those existing execution handles, plus the Open agent/Review State-writing callbacks, separately at push and passes them explicitly: the frozen row modifier never subscribes to Root’s freshly recreated permission Environment closures. The handles are cleared on pop/tab exit; a lazy SwiftUI StateObject owns only the snapshot and those handles, with isolated MainActor destruction. The nonescaping capture factory is never retained. Display closures are constructed once at push. A constant modifier chain ABOVE the equatable content transforms incoming environment keys into those same values (including helper labels and palette). Row context has explicit value equality, so unchanged presentation cannot invalidate rows; no conditional modifier branch removes/recreates the List during freeze/thaw. The project Pin/Inactive/Wake/Terminal execution guards are unchanged and resolve identity/capability from the real Store. Display snapshots never authorize an action.

On pop, the very first content construction ignores the snapshot and reads fresh status/connection/permission inputs. The Recent hold survives the push/pop, so Back refreshes text/badges without shuffling peers. A visible content construction computes ONE HomeLayout and passes it to both the project list and animation hold; entering a push constructs one additional display snapshot. The header reuses the group's computed live status. Per-agent permission/Wake/Terminal predicates are restricted to the current scope’s displayed project groups, visible helper trees, open quiet folds, attention rows and Dispatchers; closed idle/quiet rows and other scopes get no per-agent predicate calls. The generated test budgets each push to exactly one snapshot and at most two content constructions. A memoized display projection for visible Home remains a separate follow-up.

Recent uses CompanionListHold for the whole Home TAB session, including pushed routes. Activity/status/text changes update rows without sorting held peers. New projects/agents append after existing peers in catalog order, helpers stay under their real parent, and removals disappear. Newly displayed peers join the hold. Scope/sort/generation stamps reject callbacks belonging to an earlier session, including an alphabetical→Recent round trip. A tab switch away, desktop scope/sort change, or .background ends the session; .inactive (Control Center, Face ID or other temporary interruptions) preserves it; returning to Home starts fresh. Name/custom keep their existing sort and temporary scroll hold. Pin/Inactive and active/quiet/idle membership retain their structural semantics; only recency order is held. No newcomer cue or pull-to-refresh is added.

List removal has an explicit public ScrollViewReader restore. Home-only row markers record full identities and global rectangles in a lazy StateObject, non-observable, value-only anchor holder. Geometry never writes observable Home state. A saved fully visible row (or the first intersecting row when none is contained) and its relative alignment survive tab/route changes; scope changes reset it. The owner suspends synchronously at the tab/push decision, before departure geometry can overwrite the bookmark. Restoration is queued one main turn after the first valid List-layout geometry callback, once per resume, and a value generation cancels stale queued requests. No proxy or callback is retained in the owner. A missing/closed-fold target explicitly falls back to the top. Restoration clears on interaction, suspension, target geometry aligned within 1pt (pixel/layout rounding) or at most 64 geometry callbacks. The marker is a no-op elsewhere. There is no UIKit introspection in production.

Home's project-error alert remains mounted but does not present over a pushed page or during thaw. Home clears the shared project error on pop so the inline Project error cannot replay as a second Home alert. The Project page's error behavior is unchanged from main; it stores no sticky local error.

DEBUG counters distinguish the cheap owner from content/scope/attention/layout/header/quiet construction and the actual row, agent-menu, shared-project-menu, quiet-child, connection-banner, app-update-link, desktop-chip and combined-linked-row bodies. The finished-row TimelineView’s independent 60s label ticks are explicitly EXCLUDED from these counters; they use finished-run values, not live Store/attention sources. The real-Root hosted fixture uses 4 generated desktops, 96 projects and 1,152 agents with linked copies. Both Dispatch-hidden and pushed-agent tests accept 100 chunks in ten independently rendered batches. The pushed case requires zero expensive-counter changes, including row/menu children, and checks current connection presentation on the first pop construction. Other cases cover stale frozen activation, same-session Recent order, inactive-versus-background lifecycle behavior, sort/scope resets, Pin/idle section moves, and saved anchor alignment within 8pt after both a tab round trip and a push/pop, including the issued target ID. Sort tests wait for an actual alphabetical content render before returning to Recent, so coalesced preference writes cannot bypass the transition. Only tests traverse their own UIKit List. A real UI edge swipe asserts title/back label/nonblank content before and after; mid-gesture continuity is recording evidence ONLY, never a claimed assertion.

Package session tests count activity-provider calls and cover status/new/removed peers, fresh order, Name/custom and helper ancestry. Existing AgentTree/AgentRow and shared row/menu tests remain unchanged. The baseline reproduces hidden work; the first after-tree hosted run exposed five new-test failures. Their original receipts and bundles are preserved. Corrected-head checks remain pending; user policy allows self-admission through guarded FIFO tickets with simulator order coordinated between helpers. No CPU-percentage or battery claim follows from hosted counters alone; installed-configuration performance measurement remains separate.

The scroll bookmark owner is also a lazy `StateObject` with no published fields or change notifications. It exists before the first List geometry callback, so first-mount tracking does not depend on owner/content `onAppear` order. Its scalar generation and presented flag cancel stale deferred restores; teardown remains ARC-only. The render-session execution handles have isolated MainActor destruction.
