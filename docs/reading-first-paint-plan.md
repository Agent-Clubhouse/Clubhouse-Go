# Reading bookmark-first opening (#582)

PR584 is a draft. The user approved a new UX after the earlier ID-positioning experiment failed: a reopened paused transcript starts WITH its saved canonical entry as the first loaded message. Earlier history is behind Show earlier messages. This is an explicit replacement of the earlier expanded-prefix contract, not a tolerance change. It is outside beta.3 and requires independent exact-head runtime and current-main coverage acceptance.

## Product boundary

A lazy immutable StateObject computes one value-only opening seed per actual mounted full target. Discarded parent initializers, streaming and mounted history reloads do not recompute the seed. The transcript subtree owns reading State; composer/header/draft State remains above it. Initial, retained-tab return, native destination and A/B switch share this boundary.

A valid paused bookmark resolves its canonical visible entry once. An opt-in TimelineWindow starts exactly there, including an existing slice within a long reply; older rows are not prepared. A per-mount cursor remains stable under streaming and reload. Explicit Show earlier/previous-page actions can only move it earlier; Show-in-chat can only widen it. Latest ends the opening boundary and uses the normal bottom path. A removed boundary is cleared on generation replacement and cannot resurrect. This does not write a new ScrollPosition: the mounted reader stays under A’s existing missing-entry offset fallback. A nil predecessor also clears the boundary so Show earlier falls back to the normal widened window. Missing, removed, invalid-slice and old-session opening IDs have the existing deterministic normal-tail/bottom fallback. Grouped-question aliases choose the visible group without mutating the semantic bookmark.

Valid paused openings seed ScrollPosition(edge:.top); following/missing-ID openings seed bottom. The stopped onAppear proxy experiment and opening ID/handoff machinery are removed. There is no implicit ID owner to release at idle. Phase tests therefore assert ZERO active AND idle identity writes, and the real native drag still proves ownership and no late handoff. No Task, paint delay, opacity, animation, guessed numeric offset or UIKit introspection is added.

Show earlier stays inline above the first message. “At the top” means the canonical entry is the first message below the visible existing header/control/padding. Short bookmark-first content uses top alignment; following content retains bottom alignment. Product A subsequently restores the saved fractional distance using its unchanged six-point contract, retarget and20-attempt/2-second budget. Per-route video must show movement no greater than measured header/padding + saved distance +6pt, with the canonical row remaining at least partially visible as the top row.

Before a prefix-widening State change, capture the real reading position and set the existing restoring/pending-offset guard. Existing preference/consistent-geometry compensation holds that entry's screen position. The new recording must show every Show-earlier tap and a normal tail arrival within4pt, and eventually prove the older history is reachable. No timing workaround is accepted if it visibly jumps.

## Disclosed test changes

The new Domain/hosted tests replace windowFirstID != canonicalID with equality for paused remounts. The retained shownEntries expansion watermark does not force the older prefix back into a new paused opening. Tests cover sliced/grouped IDs, exact start, no hidden-prefix preparation, preceding-page expansion, missing/session fallback, seed-once identity, mounted reload, hidden reload and target isolation.

The zero-numeric-arrival setup derives a top-position bookmark from real identical-window geometry: distance =0.5 - measured first-entry lowerBound. Every zero-attempt/zero-command/one-save assertion remains. No assumed initialized-ID delivery or guessed height is used. All original Reading/restore/hidden method files remain byte-identical.

The original H1 strict methods now use a separately changed DEBUG fixture: start following with the normal window, scroll up, then reload the still-open history to restart A before injecting the same normal tail event. A bookmark-first remount no longer trims, so it cannot exercise H1. The fixture requires the reload's pre-tail window and lowerBound to match the saved state; the existing pin/window-change/lowerBound-shift/consistent-geometry/10-attempt/1-second/arrived gates and6pt/miss assertions remain. A NEW hosted test proves bookmark-first remounts keep their first row fixed through a mid-restore tail arrival.

A separate capture correction uses upperBound > offset +0.5pt (shared minimumVisibleExtent) so a numerically touching row is not saved as visible. Value tests cover equal-edge,+0.4,+0.6 and identical restored offsets. A's target correction, tolerances and budget are unchanged.
