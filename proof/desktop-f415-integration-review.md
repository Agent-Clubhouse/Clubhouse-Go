## Remaining exact client incompatibilities and bounded fixture gaps

1. **Future v2 needs two additive error-evidence decoders.** Current Go `AnnexCommandReceipt` has neither top-level `contract` nor top-level `transition`. It preserves failed/409 receipts and their error, but would discard failed-after-creation evidence and the new retained-preparation/persistence-uncertain fields. `retainedPreparation` has persisted:false/savedUnchanged:true; `unverifiedPersistence` deliberately has both null. Those states must remain distinct. A future client must read both evidence shapes before classifying an error; absent contract (already-running, authority, epoch and malformed refusals) remains unknown. This is an integration prerequisite, not an unsafe v1 success path or a request to change the current v1-only #610.
2. **Do not conflate compatibility with v2 readiness.** A v1-compatible host may advertise v2 but current Go still must not send v2 or interpret managed-composition as native-primary equivalence. The new legacy fixtures cover the supported native v1 route; they do not establish an old host's v2 response. `unsupportedVersion` uses contractVersion3 on the new host, while `oldHost` remains capability-only. An explicit v2-to-old-host refusal fixture is still useful for future negotiation tests; absence of v2 capability already prevents that request.
3. **Some documented selection failures still lack dedicated wire examples.** No complete same-provider model/context-review refusal, fallback/unavailable/expired/future catalog, unknown-field or selected-id-default refusal appears in these 36 pairs. `catalogStale` is a stale token result, not a distinct catalog-freshness refusal. Saved-default preview plus staleApplyDefaults demonstrate the wire behavior but contain no before/after generation witness; their generation binding needs desktop implementation tests, not inference from equal nullable values or normalized tokens.
4. **Keep observation scope conservative.** Early refusals still use running.state:not_running with unknown evidence. The revised document clarifies this command's creation scope; future UI must say no creation observed for this request, not infer that no agent runtime exists. Even successful replay's normalized timestamps are fixture values, not current runtime evidence.
5. **Tri-state encoding and scope checks remain required future work.** Model selected/provider_default/omitted and effort omitted/null/string cannot be represented by one encodeIfPresent optional. Validate epoch/command/target, effective and stored provider, value/source, normalized intent, persistence semantics and fresh exact saved snapshot plus nextWake token. No automatic v1 downgrade or alternate runtime/wrapper/provider is authorized after a v2 refusal or uncertainty.

The retained-native-preparation examples truthfully require fresh read/review and permit partial or replaced bytes; they do not authorize rollback/retry or claim atomic multi-file recovery. This review does not validate desktop implementation, marker/filesystem/PTY behavior, production security, installed versions or the original phone incident. #610 continues unchanged on reviewed v1 source `760efb198` and its independent runtime gates.
