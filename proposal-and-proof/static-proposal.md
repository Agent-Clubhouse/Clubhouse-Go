# #582 proposal: seed the mounted transcript from its semantic bookmark

Base: main 77b24899 (#583 merged). Branch: fix-582/first-paint. No product edits yet. PR title will use “(Refs #582)”; device acceptance remains separate.

## Source diagnosis

CompanionConversationView currently creates four independent State defaults: followLatest=true, atLatest=true, shownEntries=initialEntryLimit, ScrollPosition(edge:.bottom). The transcript's first body builds CompanionTimelineWindow without retaining the paused entry. Only the historyRevision task later reads the Store's per-target bookmark, widens shownEntries, changes following, and starts bounded restoration. That permits a real latest-window/latest-edge paint before the paused semantic choice is applied.

The Store already owns one CompanionReadingBookmark per full CompanionTarget. Its position/geometry are observation-ignored; only followsLatest is observable. Root dispatcher tabs and pushed destinations have .id(target), Review pages are ForEach(target). A managed tab preserves the outer View State but removes content while hidden; isVisible=false is its existing geometry-unmount authority. Navigation uses the existing onDisappear path. These lifetime distinctions must be tested, not inferred from a pure seed initializer.

## Proposed product delta

Replace only the four reading State values with a lazily created mounted reading-state holder. Keep composer/draft/focus/header state in place. Use a lightweight State lifetime cache with no dependency creation in its initializer; state(for: fullTarget, make:) creates an observable value holder only when the transcript actually accesses it. It returns the same holder across repeated body/initializer evaluations for that target. A changed target cannot reuse another target's holder, even in a hosted same-identity root replacement. The holder owns only followLatest, atLatest, shownEntries and ScrollPosition; it does not own a Store, runtime, client, task, viewport or sink.

On first access, copy semantic bookmark data: followsLatest; shownEntries (honour an existing/paused bookmark, with the current initial limit for a never-mounted fresh/latest chat); initial edge bottom for latest, top for paused. Seed atLatest from followsLatest until real geometry supplies the answer. Use the existing bookmark entry ID to retain the correct timeline window. No saved numeric offset is installed before real layout. The cache factory reads the bookmark lazily, so discarded View initializers neither read Store nor allocate dependencies.

Clear this mount-only cache at the same existing unmount authority as geometry: managed isVisible=false, or navigation onDisappear when isVisible==nil. Recreated retained-tab content therefore seeds from the current bookmark on its first body while composer State remains retained. Keyed clearing must not erase a newer target's state; preserve the managed-tab late-onDisappear protection. History/session revision handling stays in the existing task: it rejects old geometry and validates the semantic entry. Do not reset mounted state on every body, stream event or history refresh, and do not change the existing policy for a missing saved entry. All bindings and navigation actions resolve the current target's mounted state.

Leave product A's lower-bound correction, 20 attempts/2 seconds, touch/phase/navigation cancellation, exhaustion preservation, save guards and frame-coordinate path unchanged. No opacity, hidden transcript, delayed first paint, guessed pixel target, UIKit introspection or new conversation-dictionary observation.

## Revision after QA direction review (before code)

Use the simpler transcript-child scope, not the keyed cache. Extract the existing timeline builder and reading-only helpers into a private `CompanionConversationTranscript` View. Its four State values (plus existing reading-only debug/control State) live inside the subtree that is already removed by `isVisible=false`. Parent composer/draft/header State stays in CompanionConversationView. Give the child `.id(target)` so a same-identity parent target change cannot share reading State. The initializer copies only semantic values from the already Store-owned bookmark; constructing/discarding a child View creates no holder, service, task, viewport or dependency. SwiftUI retains its original State on ordinary parent initializer/body recreation. Existing onDisappear/managed-visibility geometry authorities remain exactly as today; no cache or manual State reset required.

Pass the existing header and entry builders as ViewBuilder closures and the existing composer-dismiss action, rather than moving the composer or changing row/menu logic. This is a mechanical extraction first; final diff will separate moved code from behavioural edits. The same-target historyRevision task, including window widening and stale-geometry rejection, remains unchanged. No historyRevision key, no reseeding during reload/resync/streaming. Explicit hosted controls cover reload while paused/open and while hidden, with exactly one new seed on re-show.

For a paused bookmark with an entry ID, seed ScrollPosition(id: saved.entryID, anchor:.top), using the SDK's public initializer, with scrollTargetLayout on the existing stack of entries. The latest path retains the bottom-edge seed; the existing missing-entry/old-session fallback stays with the unchanged history task. First-frame evidence must cover a bookmark below the loaded window's first row (earlier messages expanded), proving ID positioning rather than assuming the window starts at the bookmark. Measure the first rendered bookmark's distance and label this row-level semantic paint, not six-point final restoration. Verify alias/grouped-entry IDs before deciding whether a tiny canonical-ID adapter is needed; do not add guessed offsets or alter window bounds just to pass.

Allow Latest from the paused semantic seed until the first nonempty live metrics arrive, then use actual geometry immediately. This provisional control state must neither save a position nor cancel restoration. All post-layout six-point/prefix/cancellation and scrolling assertions remain unchanged. New scrollTargetLayout must be covered by the existing gestures, native top, rotation, streaming and Latest controls, as well as first-frame measurements. No new actor-holder teardown policy is necessary if the extraction remains values/closures only; check compiled gate regardless.

Please confirm this revised, narrower product shape before implementation; the original cache design is superseded.


## Current cumulative revision: lazy immutable mount seed and idle-only handoff

The former eager initializer and the former empty-position cancellation are rejected and superseded. The current product/test proposal is in docs/reading-first-paint-plan.md. CompanionReadingSeed uses a StateObject autoclosure to compute immutable semantic values once per mounted full target. The child only copies that cached seed. DEBUG counters prove no additional seed/slicing work under parent redraw, paused or following streaming, or open reload. On cancellation no binding is written during active phases or user ownership, and navigation-away writes nothing. A still-owned ID can become the measured point only at idle. Hosted phase injection on a real native scroll view (plus a DEBUG ownership guard override) is disclosed; the original real-drag UI test is unchanged. Arrival controls use a nonzero 0.5pt saved distance within the unchanged 1pt arrival criterion, plus a separate 40pt numeric-correction case.
